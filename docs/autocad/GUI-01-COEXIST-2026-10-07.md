# GUI-01 후속: 사용자 GstarCAD 공존 보호 실기

## 결론

사용자가 GstarCAD 2026 Standard에서 미저장 표시가 있는 업무 도면을 열어둔 상태에서 최신 검증용 frozen APP의 폴더 입력 변환을 실행했다. 정상7개 모두 성공했고 사용자 CAD는 유지되며 APP이 생성한 별도 CAD1개만 종료됐다. 제품 코드·설정·EXE는 수정하지 않았다.

## 확인된 사실

| 항목 | 결과 | 확인 방법 |
| --- | --- | --- |
| 기존 사용자 CAD | 1개 유지 | PID 및 생성시각 전후 동일; 변환 중0.5초 간격 모든 관측에서 유지 |
| 열린 사용자 도면 | 창·도면 탭·미저장 표시 유지 | Computer Use로 전후 같은 창과 화면 관측; 입력·저장·종료 명령 없음 |
| APP CAD | 새1개 생성 후 종료 | 관측 최대 CAD2개, 종료 후 새 PID 없음 |
| 실제 업무 변환 | 7/7 성공, 종료코드0 | 최신 frozen EXE 명령행 폴더 입력 |
| 배치 시간 | 33.15초 | EXE 실행부터 종료까지; CAD 시작·종료 포함, GUI 선택 시간 없음 |
| 원본 | 7/7 보존 | 파일 SHA-256·수정시각 전후 동일 |
| 출력 PDF | 7개, 각1페이지·비공백·비암호화·약297x210mm | PDF 구조 검증 |
| 출력 비교 | 7/7 동일 | 이전 GUI 폴더 입력 출력과 전체 페이지 RGB 렌더 픽셀 비교 |
| 대표 PDF 육안 | 기존과 동일한 도곽·방향 | 첫 도면 렌더 확인; 기존 잔존 색상·조밀한 문자는 그대로 허용 |

실행 파일 SHA-256: `09883ED375E8EFB43700B5B037BF5D012976666B5CD16AF188B86CCEC44DD85E`. [GUI-01 인계](GUI-01-HANDOFF-2026-10-07.md)의 검증용 EXE와 동일하다. 검증 당시 소스 HEAD는 `b4b9aed28f8e88d344405f31d3b52227b25c744b`다.

## 진단 이력과 한계

첫 진단은 검증 스크립트의 pywin32 DLL 초기화 순서로 APP 시작 전에 중단됐다. 작업용 스크립트에 기존 어댑터와 동일한 `pywintypes` 선행 초기화를 적용하고 재실행했다. 이 실패를 APP 변환 실패나 PASS에 합산하지 않는다. CIM 조회도 환경 접근 제한으로 불가하여 실제 검증은 제품의 읽기 전용 PID 열거와 프로세스 생성시각 조회를 사용했다. 영구 권한·보안 설정은 변경하지 않았다.

사용자 CAD의 프로세스·창·화면 및 미저장 표시 유지 근거이며 미저장 메모리 객체 전체의 내용 동일성을 직접 감사한 것은 아니다. 관측 주기 사이의 모든 순간을 보장하지 않는다. 사용자 CAD1개와 업무 도면7개를 대상으로 한 현재 PC 사례이며 다른 제품·다중 사용자 CAD·다른 PC로 일반화하지 않는다.

네트워크/클라우드 접근 불가 경로, 최신 AutoCAD 실기, 타PC 검증, 설치본 교체·공식 배포는 이번 시험 대상이 아니다. 제품 수정이 없어 전체 pytest를 이번 공존 시험에서 재실행하지 않았으며 직전 MAIN의931 PASS/13 SKIP은 [로컬 통합 기록](../releases/2026-10-07-local-main-integration.md)의 별도 실행이다.

## 증거·후속 작업

개인 로컬 증거는 `.pytest-tmp/gui1-coexist-check.py`, 최초 실패 로그, 재실행 로그, `gui1-coexist-results.json`, APP 로그 및 PDF/렌더에 보존한다. 고객 도면·출력·개인 경로·PID는 Git에 포함하지 않는다. 창 관측은 현재 대화의 Computer Use 실행 기록에 남겼다.

현재 PC 공존 보호의 NOT_RUN 항목은 위 범위에서 충족했다. 다음 권장 작업은 GUI-01 번들을 사용한 타PC 검증 키트 갱신 및 다른 PC 실기다. GitHub 게시·Desktop 설치본 교체·공식 릴리스는 이번 공존 검증으로 수행하거나 승인된 것으로 간주하지 않는다.
