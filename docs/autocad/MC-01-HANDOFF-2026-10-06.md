# MC-01 구현·검증 인계 — 2026-10-06

## 결론

승인 REV01의 AutoCAD 흑백 준비를 공통화하고 GstarCAD 플롯 전에 연결했다. 실제 GstarCAD2026의 승인1:1 표본1종은144dpi에서 잔존 색상0이며 A4가로/판정/원본·기존 CAD 보호가 확인됐다. 그러나 객체별 COM 준비에45초 이상이 추가되어 파일 처리 시간이 약12배로 증가했다. **속도 개선 완료가 아니며 MAIN·배포에 반영하지 않는다.**

상태: HANDOFF_READY / MC-S1 승인,MC-S2 부분 검증. 사용자 선택6.1 Sol Medium 유지. 모델 변경 필요성 없음. 작업 브랜치 `codex/gstarcad-main-regression`; 기준 HEAD `d3d75520642a597e8c8de9b45eea3be42dc67505`, MAIN `c951b818035ac6a06dce7b9a464cadb050bdc808`.

## 확인된 변경

- `cad/monochrome.py` 공통 준비,기존 AutoCAD 경로 재수출. 두 어댑터가 판정 후 플롯 설정 전에1회 호출한다.
- RGB 순백색은 유지하고 나머지 RGB를 ACI7로 바꾼다. 기존 ACI/상속 색상·형상·문자·Lineweight/PlotStyleName은 쓰지 않는다.
- 기존64블록/누적5000객체 한도를 유지한다. 읽기·한도·XRef 오류는 첫 변경 전에E410;변경 중 실패는 부분 복사본을 저장하지 않고 폐기한다.
- 독립 리뷰에서 `IsXRef` 정보 누락을 local로 간주하는 기존 fallback을 발견했다. 필수 읽기와 누락/AttributeError 실패시험으로 보완했다.
- 서비스 시험에서 부분 쓰기 실패→기존 최종PDF 보존→동일 세션 후속 정상파일 변환을 확인했다. 실제 CAD 실패격리 전체시험을 대신하지 않는다.
- 벤치마크는 준비 시간을 플롯 전체 시간 안의 별도 단계로 기록한다(둘을 합산하면 중복). 구버전 Gstar PDF 검증 함수의 시그니처 호환을 보완했다.
- 읽기 전용 감사 도구는 실행시 입력해시·현재입력해시·승인manifest를 연결하고 감사한PDF SHA256을 기록한다. `python -O`에서도 검증 조건이 제거되지 않는다. 샘플1개를 전체43PASS로 표시하지 않는다.

## 분석·리스크·NOT_RUN

확인: 추가 준비 시간은45.48초,기존 판정/플롯 자체는1초대다. 분석: 객체별 COM 왕복이 주요 병목으로 보인다. 속성별 COM 호출 수의 별도 probe는 수행하지 않았으므로 정확한 내부 비용 분포는 미확인이다. 단순 공통화/연결만으로 속도 문제를 해결할 수 없다.

- 승인43종 전체 흑백,같은 보정 OFF/ON43쌍,완전한 선굵기/가림 비교: NOT_RUN.1종에서 큰 지연을 확인하여 전체 장시간 검증 대신 성능 설계 결정을 요청한다.
- AutoCAD2021 새 변경 실기: NOT_RUN(이 PC에 없음). 과거 PC-B PASS는 이번 변경PASS가 아니다.
- 기존G3 특수시험/고객 표본 부재,G5 frozen EXE/다른PC,공식지원/배포: 미완료.
- 실제 정상서명 손상DWG의 modal/hang은 본 변경으로 해결하지 않는다. 모든 프로세스 이름 종료나 새watchdog를 추가하지 않는다.
