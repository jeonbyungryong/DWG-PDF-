# GUI-01 다른 PC 검증 키트 갱신 기록

## 결론

현재 PC에서 GUI 및 사용자 CAD 공존 검증을 통과한 동일 frozen runtime으로 새 타PC 검증 키트를 만들었다. 기존 GC-02 키트는 덮어쓰지 않고 보존했다. 제품 코드·EXE 변경은 없으며 공식 릴리스가 아니다.

## 산출물과 검증

- 파일: `dist/dwg-to-pdf-pc-validation-gui1-20261007.zip`,43,422,417바이트.
- ZIP SHA-256: `4DF56A427348BFE37D216444C72FF5FB8E4EA09A4956877E9D9C9C3B7306894B`.
- runtime260개 파일은 최신 GUI-01 번들과 개별 SHA-256 및 개수 동일. EXE SHA-256은 `09883ED375E8EFB43700B5B037BF5D012976666B5CD16AF188B86CCEC44DD85E`.
- 승인 표본43개는 기존 manifest의43개 사례와 파일 해시를 대조했다. 고객 작업 도면/PDF/개인 로그는 포함하지 않았다.
- 실제 압축 해제 파일312개: 내용 목록311개와 `checksums.csv`1개. 목록의 크기·SHA-256 및 CSV 자체 해시가 원본 키트와 모두 일치했다.
- Windows PowerShell5.1의 실제 `verify_bundle.ps1` 실행: 복사본과 ZIP 해제본 모두 종료코드0, `RUNTIME_SELF_CHECK_OK`, `VALIDATION_BUNDLE_OK`.
- EXE 없는 별도 빈 폴더를 검사하는 의도적 실패 시험: 종료코드1, `dwg-to-pdf.exe is missing.`. 보안·실행 정책 변경 없음.
- 이전 ZIP SHA-256 `495B6B27F4B228A50E98E8E867F851ED9554E49D00601D845BA4AD2767D5EBDB`는 갱신 전후 동일했다.

키트 루트에는 최신 README-KO, GC-02/GUI-01/공존 인계 및 BUILD-IDENTITY를 포함했다. runtime 안의 문서는 기존 빌드 시점 상태임을 명시했다. 절차는 [갱신된 타PC 안내](PC-VALIDATION-KIT-2026-10-07.md)를 따른다.

## 제한과 다음 작업

위 결과는 현재 PC에서의 패키징·해시·runtime 점검이다. 이 키트로43개 CAD 변환을 이번 갱신 작업에서 다시 실행한 것은 아니다. GUI와 공존 변환은 같은 EXE의 선행 실기 결과를 근거로 하며 다른 PC 실기/Python 미설치 환경/최신 AutoCAD 수용은 NOT_RUN이다. 사용자 CAD에 추가 입력·종료 명령을 보내지 않았다.

새 ZIP과 개인 검증 로그는 로컬 ignored 산출물로 보존한다. 안내·기록만 로컬 MAIN에 반영하고 GitHub 게시·Desktop 설치본 교체·공식 배포는 하지 않는다. 다음 단계는 다른 Windows PC에서 전체 폴더를 풀고 runtime 점검,43종 명령행 변환,GUI 선택 창 및 사용자 CAD 보호를 각각 검증하는 것이다.

근거: `.pytest-tmp/gui1-kit-package.log`, `gui1-kit-verify.log`, `gui1-kit-extracted-verify.log`, `gui1-kit-deliberate-failure.log`, 새 키트 checksum 및 실제 ZIP 해제본. 파일 전달 준비 성공과 타PC 수용 성공을 구분한다.
