# MC-02 — monochrome 플롯 유지·잔존 색상 허용

## 결론·승인

2026-10-06 사용자 지시 `monochrome을 적용하였을 때 흑백으로 전환되지 않는 색상은 무시하는 방향으로 진행한다`와 변경안 후 `진행해`를 적용했다. **두 CAD 모두 monochrome.ctb/PlotWithPlotStyles를 유지하지만 추가 RGB 검사·강제 색상 변환을 하지 않는다. 잔존 색상만으로 실패 처리하지 않으며 완전 흑백은 보장하지 않는다.**

기준 개발SHA `f687e6588bbb50fea4f4022a73077672b45cd668`,브랜치 `codex/gstarcad-main-regression`. MAIN `c951b818035ac6a06dce7b9a464cadb050bdc808` 및 기존 실행파일은 이번 작업으로 변경하지 않는다. 사용자6.1 Sol Medium 유지. CAD 내부 일괄 보정 개발은 불필요해져 진행하지 않는다.

## 확인된 변경과 유지 기능

- AutoCADDocument/GstarDocument의 추가 `prepare_monochrome` 호출만 제거했다. 축척·도곽·회전 판정/출력 창/PC3/CTB 설정/정상 PDF 검증은 변경하지 않았다.
- 기존 원본hash·mtime/임시복사본/단일APP소유CAD/기존사용자CAD/Close(False)/실패파일 격리/실패임시PDF제거·기존최종PDF보존을 유지한다.
- 보정 전용 XRef·색상정보·64/5000검사는 더 이상 플롯 전에 실행되지 않는다. **기존 판정용 탐색 한도·지원조건을 완화하거나 다른 템플릿을 허용한 것은 아니다.**
- 공통/이전 AutoCAD import의 보정 함수는 호환·과거 시험을 위해 보관되지만 변환 경로에서 호출하지 않는다. 보정 GUI 옵션/숨은 opt-in을 추가하지 않았다.
- 개발 감사 도구의 `--allow-residual-colors`만 명시적으로 색상실패를 허용한다. 입력해시/manifest/원본·CAD보호/페이지/용지/회전/창/비공백 검증은 유지하고 잔존색상 수·정책을 기록한다. 기본 strict mode는 과거 MC-01 감사용으로 남겼다. 런타임의 새옵션이 아니다.

## 검증 근거

새실제어댑터 시험4개가 RED→GREEN: RGB 유지,추가컬렉션 검사 없음,monochrome설정·PlotWithPlotStyles 유지,컬러잔존 PDF를 정상 처리. 부분드라이버PDF실패→임시PDF제거·기존최종보존→동일세션후속정상변환 시험을 갱신했다. 감사CLI의 strict색상실패/명시allow시성공·색상수기록 시험도 RED→GREEN으로 검증한다.

독립읽기전용정적리뷰는 코드·시험의 Critical/Important/Minor 결함 없음 판정. Reviewer는 실제CAD/전체시험을 재실행하지 않았다.

동일PC/GstarCAD2026 COM26.00/승인PC3·CTB·A4/nativeON/probeOFF의1:1표본: 파일시간 **49.63초(이전 보정)→3.89초(CTB만)**. 이전보정45.75초단계가 사라졌다. 이는1종 개별실행 비교이며 전체도면의 고정처리시간 보장이 아니다.
