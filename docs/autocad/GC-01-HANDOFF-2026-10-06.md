# GC-01 — 도면별 COM 형상 정보 재사용

## 결론

상태: **HANDOFF_READY**. 사용자 승인한 제한적 개선을 `codex/gstarcad-main-regression`, 시작 기준 `37aba454d8539644b435fb43261e0b25d414772e`에 구현·검증했다. 요청한6.1 Sol Medium 유지. LLM/API/네트워크 런타임 의존을 추가하지 않았다. MAIN·공식 릴리스·기존 EXE는 변경하지 않는다.

## 구현과 유지한 규칙

- `configure_extraction`을 임시 도면의 변환 분석 시작 경계로 사용한다. 같은 설정으로 다시 호출해도 이번 캐시와 기존 영역 캐시를 초기화한다.
- 후보별 서버 영역 선택은 유지하고, 선택된 객체의 검증된 속성은 도면 내부 handle과 읽기 형식으로 구분해 재사용한다. 빈 handle은 재사용하지 않는다.
- 도달한 실제 블록 정의의 로컬 좌표 정보를 재사용하되, 배치별 좌표 변환·회전·축척 검사·instance path와 순환 방지는 매번 수행한다. 실제 Name을 사용하며 EffectiveName으로 다른 정의를 합치지 않는다.
- 캐시 재사용 시에도 블록/엔티티 탐색 예산을 매번 차감한다. 무시한 지원 밖 객체도 엔티티 예산에 포함한다. 실패·부분 결과는 완성 블록으로 보관하지 않는다.
- 신규 엔티티/블록 캐시의 합계 보관 항목은5000개,블록 정의는64개로 제한한다. 한도 도달 시 검사를 생략하지 않고 재사용 없이 읽는다. 이 수치는 신규 캐시 항목의 상한이며 전체 프로세스 메모리나 기존 영역 출력 캐시의 바이트 상한을 뜻하지 않는다.
- 다른 도면·다음 분석에 공유하지 않는다. 등록용 읽기에는 신규 재사용을 기본 활성화하지 않는다. 원본DWG/사용자CAD 보호,단일APP소유CAD,52후보/판정 임계값,저장된 템플릿 창의 이동·회전 계산,CTB-only 플롯과 파일별 오류격리를 바꾸지 않았다.

## 성능 해석과 한계

이전 강제COM 비교에서 동일 승인1:1공란 입력은1532.859초였다. 중간 코드의108.95초 및 최종 코드의1:1공란105.09초는 이 표본에서 약93% 시간 감소를 보여주지만, 전체 표본의 고정 개선 배율이나 시간 보장은 아니다. 기동/종료·파일 단계·출력 감사의 포함 범위와 동시 작업 조건이 다르므로 엄격한 반복 통계 실험이라고 주장하지 않는다.

기본native경로는 이미43개를 수분 내 처리한 경로이며 이번 개선의 대상은 COM 대체 경로의 공란/N/A 구조 판정이다. 두 경로 시간을 섞지 않는다. 이번 기본native43종의 기동·종료 포함 분할 평균은4.47초/개다. 과거 MC-02소스197.90초,구 frozen EXE189.52초와 이번192.14초는 별도 시점/실행 형식의 단회값이며 차이를 고정 속도 개선으로 주장하지 않는다.

AutoCAD 실기,전체43 native OFF/ON 비교,G3/G5의 나머지 환경/사용자 육안 승인,다른PC/Python미설치PC,기존 고객4개 부재 입력,정상헤더 내부손상 watchdog는 별도다. 이번 검증을 전체G3/G5 완료·공식 지원·치수 의미 정확성 증명으로 표시하지 않는다. 원시 로그·고객자료·개인경로·PID는 ignored 로컬 근거에만 보관한다.

## 다음 한 단계

완료 소스와 검증 기록을 개발 브랜치/관리 이슈에 인계한다. MAIN 통합과 이번 코드의 EXE 재빌드/배포는 별도 승인 후 진행한다. AutoCAD 실기 및 전체43 native OFF/ON 비교 등 남은 게이트는 위 한계를 유지한다. 로컬 재현은 기존 `tools/benchmark_conversion.py`와 `audit_monochrome.py --allow-residual-colors`,전체pytest를 사용한다. COM6종은 검증용 프로세스 내부에서 config의native사용만false로 변경했으며 CAD 보안·시스템 설정은 변경하지 않았다. 계측/비교 스크립트와 원시JSON은 ignored `.pytest-tmp/gc1-*`에 보존한다.
