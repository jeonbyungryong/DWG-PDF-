## 진행·미검증 범위

- 특수 시험5개는 실제 COM 순차3종/원본·사용자CAD보호,원래 윈도우 학습2종의 저장창 독립성,기준 구조점수3종,13종 내부축척 판정,계산창 PDF순차출력3종과 의도적 lifecycle실패 뒤 임시도면정리를 검사했다. 판정·출력은 통과했고 사용자CAD2개만 남은 것을 확인했다.
- native OFF/ON43종 전체 비교는 **사용자 승인으로 중단**했다. OFF에서 18개 완료 뒤 19번째 N/A 도면 분석 중 정확한 소유 프로세스 핸들·실행경로·생성시각을 재확인하여 앱 소유 CAD만 종료했다. 전체 pytest는 종료코드1,1 failed/3301.84초이며 중단에 따른 RPC·문서닫기 오류를 제품의 자연 실패나 PASS로 해석하지 않는다. ON 비교는 미실행. 세션 최종 기록에서 원본 hash/mtime 보존·기존 사용자CAD 보존·소유CAD 종료를 확인했다. 최초 pytest 준비의 WinError3은 CAD 실행 전 상위 임시폴더 부재였으며 별도 준비오류 로그를 보존했다. CAD 배치는 병렬 실행하지 않는다.
- 정상 헤더 내부손상 DWG의 모달 대기·복구는 아직 미검증. [승인 명세 §9](../superpowers/specs/2026-10-02-autocad-support-design.md)의 별도 watchdog 승인 게이트를 유지한다. 현재 명백한 잘못된 헤더의E203 차단을 이 항목의 PASS로 대체하지 않는다. 안전한 외부 watchdog/소유권증명이 없는 임의 손상 입력을 실행하지 않는다.
- 사용자 최종 육안 승인 및 다른PC/Python미설치PC G5는 별도다. 모든 GstarCAD 검증이 끝났다고 주장하지 않는다.

## COM 지연 분석 및 다음 단계

확인된 사실: 강제 native OFF 비교에서 `TEMPLETE_1대1_blank.DWG`는 변환을 완료했으나 파일당 1532.859초(약25분33초)가 걸렸다. 같은 제품의 기본 native 경로 frozen43종은 총189.52초에 완료했다. 강제 OFF 시험의 지연을 기본 경로 전체의 성능으로 일반화하지 않는다.

코드 추적과 실제13프로파일의 후보 구성 확인 결과, 공란/N/A 구조 비교는13프로파일×4회전=52후보이며 frame cache key도52개 모두 다르다. `choose_profile_by_structure`→`verify_rotation`→`filtered_geometry_snapshots`가 후보별 서버 영역조회와 선택 엔티티/도달한 블록 속성 추출을 반복한다. 현재 `_geometry_cache`는 동일 영역에만 적용되어 이 반복을 줄이지 못한다. 반복 COM 속성 추출은 개선 대상이며, 전체1532.859초 중 각 세부 단계 비중은 계측 전으로 `[확인 필요]`다.

권장 수정안은 분석 구간에 한정한 도면별 엔티티/도달 블록 스냅샷 재사용이다. 후보별 서버 영역 선택·52후보 전체 비교·기존 임계값·블록/엔티티 예산·오류 전파를 유지하고, 다른 도면으로 캐시를 공유하지 않는다. 아직 제품 코드에 적용하지 않았으며 짧은 설계 승인 뒤 재현 테스트·COM 호출 계측·공란/N/A/회전/예산 및 원본·CAD 보호 회귀로 효과를 검증한다. 목표 시간이나 개선 배율은 현재 보장하지 않는다. watchdog/MAIN/공식 배포는 이 수정안에 포함하지 않는다.
