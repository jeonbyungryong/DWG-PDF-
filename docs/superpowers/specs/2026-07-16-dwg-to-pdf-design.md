# 로컬 DWG → PDF 자동변환 프로그램 설계 명세

- 문서 상태: 사용자 승인 설계의 기록본
- 승인일: 2026-07-16
- 기준 개발지침: `CODEX_DWG_TO_PDF_개발지침_260715_REV02.md`
- 대상 환경: Windows 10/11 64-bit, GstarCAD 2026 이상
- 프로그램 형태: GUI 없는 로컬 콘솔 프로그램

## 1. 결론

주 변환 경로는 **Python 콘솔 애플리케이션 + 전용 GstarCAD COM 세션 + 결정론적 템플릿 프로파일 매칭 + pypdf 결과 검증 + PyInstaller onedir 배포**로 한다.

외부 서버, 온라인 변환, LLM, 텔레메트리는 사용하지 않는다. `cad2x-converter`, LibreDWG, ezdxf는 주 변환 경로에 포함하지 않으며, 별도 승인된 비교 PoC 또는 진단 경로로만 취급한다.

## 2. 범위

### 2.1 포함 범위

- 한 개 이상의 DWG 또는 DWG가 있는 폴더 입력
- 사용자가 매 실행마다 지정하는 PDF 출력 폴더
- 13개 축척 기준 템플릿의 등록, 해시 검증, 승인 상태 관리
- 작업용 DWG 파일명과 무관한 내부 `Scale` 셀 기반 축척 판정
- 단일·다중·혼합 축척 도곽의 탐지와 개별 PDF 출력
- 내부 Scale과 도곽 Anchor로 대상 Plot Window를 새로 계산
- A4 가로, Fit to Paper, Center Plot, `monochrome.ctb`, 선가중치 적용
- 기존 PDF 충돌의 덮어쓰기·복사본·건너뛰기 승인
- 원본 DWG 비변경, 임시 복사본 사용, 원자적 PDF 저장
- 로컬 로그, PDF 유효성 검사, 독립 실행형 onedir 배포

### 2.2 제외 범위

- 폴더 상시 감시와 무인 서버 운영
- 온라인 자동 업데이트와 런타임 의존성 다운로드
- GUI 매크로, 화면 좌표 클릭, 이미지 인식 기반 플롯
- 등록되지 않거나 모호한 도곽의 임의 출력
- GstarCAD 자동 설치·라이선스 활성화
- 다중 페이지 PDF 병합

## 3. 확인된 개발 전제

- GstarCAD 2026 Standard COM 26.00과 `GStarCAD.Application.26` ProgID가 동작한다.
- `DWG To PDF.pc3`, `monochrome.ctb`, Canonical Media `A4`가 설치되어 있다.
- 템플릿의 `User77` 용지는 COM 측정값 297 × 210 mm이다.
- 13개 템플릿의 Model 탭에는 Window 플롯 설정이 저장되어 있다.
- 수정된 `TEMPLETE_5대1.DWG`도 나머지 템플릿과 동일한 플롯 조건을 만족한다.
- 1:1과 5:1 템플릿에서 실제 `%PDF-1.7` 출력과 원본 SHA-256·수정시간 불변을 확인했다.
- 1:1과 1:2 대표 템플릿 내부에서 각각 `1대1`, `1대2` 축척 토큰을 확인했다. 전체 13개 토큰은 등록 단계에서 다시 검증한다.
- 향후 작업용 DWG 파일명에는 축척 정보가 없으며, 각 도곽 우측 하단의 `Scale` 글자 바로 아래에 `1:1`, `2:1` 등의 축척값이 존재한다. `Scale`과 축척값의 상대 위치는 제공된 템플릿 규격에서 일정하다는 사용자 운영 조건을 적용한다.
- 작업 도곽 전체는 기준 템플릿에 대해 X/Y 이동과 0°·90°·180°·270° 회전이 가능하며, 대상 DWG에 저장된 Plot Window 위치·크기는 신뢰하지 않는다.
- 2026-07-16 추가 샘플에서 1:1 도곽은 실제 420 × 297인데 저장 Window가 약 148.08 × 98.32였고, 1:50 도곽은 실제 21,000 × 14,850인데 저장 Window가 약 37,280 × 31,995였다.
- 두 COM 인스턴스 생성 시 별도 GstarCAD 프로세스가 관찰됐으나 종료 응답이 불안정했다. 전용 프로세스의 소유권 추적과 복구 정책이 필요하다.

## 6. 주요 컴포넌트와 인터페이스

### 6.1 CLI와 작업 조정기

- 입력: 명령행 DWG/폴더 목록, `--output`, `--config`, 템플릿 관리 명령
- 출력: 작업별 성공·실패·보류 결과와 종료 코드
- 책임: 처리 순서만 조정하며 COM, 기하 계산, PDF 파싱을 직접 수행하지 않는다.

### 6.2 환경 검사기

- GstarCAD 제품·버전·ProgID·실행 파일 경로 확인
- `DWG To PDF.pc3` 정확 일치 확인
- 선택 플로터의 용지 목록에서 297 × 210 mm 후보 확인
- `monochrome.ctb` 존재와 도면 CTB/STB 모드 확인
- 공통 환경 오류는 DWG를 열기 전에 전체 중단한다.

### 6.3 전용 COM 세션

- 작업 시작 전에 프로세스 Mutex를 획득한다.
- 사용자 GstarCAD 인스턴스에 `GetObject`로 연결하지 않는다.
- 새 COM 인스턴스를 만들고 생성 전후 PID 차이와 HWND를 기록해 소유 프로세스를 판정한다.
- 동시에 제어하는 GstarCAD 세션은 한 개로 제한한다.
- **작업 DWG 한 개마다 새 GstarCAD 프로세스를 생성**하고 열기→검사→플롯→닫기를 완료한 뒤 다음 파일로 넘어간다.
- 파일 열기, 축척 판독, 플롯, 종료를 별도 타임아웃 단계로 관리하고 체크포인트 로그를 남긴다.
- ModelSpace 전체 `foreach` 열거와 Blocks 컬렉션 전체 재귀 열거를 금지한다.
- 정상 종료가 실패하면 COM 해제→유예 대기→소유 PID 확인→소유 PID만 종료 순서로 복구한다.
- 사용자 소유 또는 소유권이 불명확한 프로세스는 종료하지 않는다.

### 6.4 템플릿 프로파일 저장소

프로파일은 JSON Schema로 검증하며 다음을 저장한다.

- 스키마·프로파일 버전, 승인 상태, 승인 시각
- 축척 라벨과 분자·분모
- 기준 DWG 파일명, SHA-256, 수정시간, DWG·GstarCAD 버전
- Model/Layout 이름과 기준 템플릿의 승인된 참조 Plot Window
- 플로터, Canonical Media, 실제 용지 크기, 회전, CTB, 플롯 옵션
- 도곽 종횡비, 후보 영역의 필터된 엔티티 유형 히스토그램과 레이어 집합
- 블록 이름과 정규화 삽입점
- 외곽·제목란 Anchor의 정규화 좌표
- 기준 도곽 네 모서리와 회전 판별용 비대칭 Anchor의 로컬 좌표
- 우측 하단 `Scale` 라벨 객체의 정규화 경계·삽입점
- `Scale` 라벨 아래 축척값 객체의 정규화 경계·삽입점과 상대 벡터
- 축척값 검색 영역과 상대 위치 허용 오차
- 허용 변환과 교정 데이터셋 버전
- 매칭 가중치·임계값·최소 점수 차이

기준 DWG 해시가 달라지면 승인 상태를 즉시 무효화하고 E308을 반환한다.

## 7. 기준 템플릿 이름과 작업용 DWG 내부 Scale 셀

### 7.1 기준 템플릿 파일명 정규화

아래 규칙은 **기준 템플릿 등록에만** 사용한다. 작업용 DWG 파일명은 축척 판단에 사용하지 않는다. 기준 템플릿은 대소문자를 구분하지 않고 다음 형식을 허용한다.

```regex
^(?:(?:TEMPLETE|TEMPLATE)_)?(?P<numerator>\d+(?:\.\d+)?)대(?P<denominator>\d+(?:\.\d+)?)$
```

- `TEMPLETE_1대2.DWG` → `scale_label = 1대2`
- `TEMPLATE_1대2.dwg` → `scale_label = 1대2`
- `1대2.dwg` → `scale_label = 1대2`
- 그 외 접두어·접미어가 있으면 E305로 거부한다.

작업용 DWG 파일명은 축척 문자열이 없는 일반 업무 파일명으로 취급한다. 파일명은 입력 식별과 최종 PDF 기본 이름에만 사용하며, 파일명에 우연히 `1대1` 같은 문자열이 포함돼도 축척 판정 근거로 사용하지 않는다.

### 7.2 Scale 셀 학습과 축척 판정

각 기준 템플릿을 등록할 때 우측 하단 제목란에서 `Scale` 라벨과 그 바로 아래 축척값의 위치 관계를 학습한다. 여기서 학습은 외부 AI나 OCR이 아니라 GstarCAD COM으로 Text, MText, Attribute 객체를 읽어 정규화 좌표 프로파일을 만드는 결정론적 등록 절차다.

등록 절차는 다음과 같다.

1. 도곽 경계와 제목란 Anchor를 확정한다.
2. 도곽 우측 하단의 학습 영역과 겹치는 Text/MText/Attribute/Block Reference만 필터 선택한다.
3. `Scale` 객체 아래쪽의 근접 객체 중 숫자 축척 패턴을 만족하는 값을 찾는다.
4. `Scale` 객체와 축척값 객체의 경계, 삽입점, 상대 벡터를 도곽 좌표로 정규화한다.
5. 내부 축척값을 기준 템플릿 파일명의 축척 라벨과 비교한다.
6. 두 값이 일치하는 경우에만 프로파일을 등록한다.

작업용 DWG의 각 도곽에서는 전역 우측 하단이 아니라 회전된 도곽의 학습 상대 위치에 해당하는 `Scale` 셀만 검사한다.

- `Scale` 라벨이 학습 위치와 허용 오차 내 존재해야 한다.
- 바로 아래 축척값이 `1:1`, `2:1`, `1대2` 등의 허용 패턴으로 파싱돼야 한다.
- 파싱된 내부 축척값으로 후보 프로파일을 선택하고, 도곽 형상 지문과 Plot Window 변환 잔차로 다시 검증한다.
- 하나의 DWG에 여러 도곽이 있으면 도곽별 `Scale` 셀을 독립적으로 읽어 서로 다른 축척을 판정한다.
- 작업용 DWG 파일명은 이 과정에 참여하지 않는다.

- 허용 토큰: `1:1`, `1대1`, `1 : 2` 등 숫자 축척 패턴
- 저장 값: `Scale` 라벨·정규화 축척 토큰·상대 위치·객체 유형만 저장
- 저장 금지: 전체 도면 텍스트, 개인정보 가능성이 있는 문자열
- 기준 파일명 라벨과 내부 축척 토큰이 다르면 등록을 중단한다.
- 학습 위치에 `Scale` 라벨 또는 축척값이 없으면 E303으로 보류한다.
- 내부 축척값과 형상 프로파일이 서로 모순되거나 복수 후보가 남으면 E304로 보류한다.
- 도면 내 다른 주석에 있는 축척 문자열은 검색·판정 대상으로 사용하지 않는다.

### 7.3 제한 탐색 규칙

사전 테스트에서 11,603개 ModelSpace 객체의 전체 열거와 블록 정의 전체 열거가 GstarCAD COM RPC 정지로 이어졌다. 따라서 운영 구현은 다음 제한 탐색만 허용한다.

1. EXTMIN/EXTMAX는 서버 측 필터 탐색의 외곽 한계와 비정상 좌표 검사에만 사용한다. 대상 DWG의 저장 Plot Window는 후보 생성에 사용하지 않는다.
2. GstarCAD SelectionSet의 DXF 유형 필터로 도면 범위의 `INSERT`, `TEXT`, `MTEXT`, Attribute만 요청해 `Scale` 후보를 먼저 찾는다.
3. 후보 영역과 겹치는 최상위 Block Reference만 선택한다.
4. 선택한 블록 정의와 그 안의 중첩 블록만 방문 집합을 사용해 재귀 탐색한다.
5. 각 `Scale` 후보에 대해 선택된 축척 프로파일의 0°·90°·180°·270° 도곽 위치를 역산하고, 예상 모서리 주변만 추가 필터 선택한다.
6. 익명 블록 이름은 식별자가 아니라 탐색 경로로만 사용하고, 최종 판정은 `Scale` 값·상대 위치·도곽 크기·회전 Anchor로 수행한다.
7. 필터 선택이 실패하거나 제한 탐색이 타임아웃되면 전체 열거로 폴백하지 않고 E303으로 해당 도곽을 보류한다.

탐색 한도와 타임아웃 값은 실제 20~30개 교정 세트에서 확정하며 설정 파일에 숫자형으로 저장한다.

## 8. 도곽 후보와 매칭

### 8.1 후보 생성

다음 순서로 후보를 생성한다.

1. 서버 측 유형 필터로 찾은 `Scale` 라벨과 바로 아래 축척값 후보
2. 내부 축척값과 일치하는 승인 프로파일
3. Scale Anchor에서 역산한 0°·90°·180°·270° 도곽 후보
4. 예상 모서리 주변의 주요 Block Reference, 닫힌 Polyline 또는 연결된 Line
5. 기준 크기·종횡비·비대칭 회전 Anchor와 허용 오차가 맞는 영역
6. 중복·포함·과도한 겹침 제거

대상 DWG의 저장 Plot Window는 로그에만 기록하고 판정과 출력에 사용하지 않는다. EXTMIN/EXTMAX는 필터 탐색 한계와 계산된 도곽의 포함 여부를 확인하는 보조값이며, 내부 `Scale` 셀과 Anchor 검증을 대체하지 않는다. 도면 전체 객체 전수 열거와 가장 큰 사각형 자동 선택은 사용하지 않는다.

### 8.2 허용 변환

- X/Y 이동
- 0°, 90°, 180°, 270° 회전
- 미러는 교정 샘플에서 별도 승인된 프로파일만 허용

선택된 축척 프로파일의 예상 도곽 크기에 대해 수치 오차만 허용한다. 임의 균일 확대·축소, 비균일 축척, Shear, Anchor 누락, 외곽 단절은 E307로 보류한다.

### 8.3 점수 구성

각 점수 성분을 0~1로 정규화한다.

- 외곽 종횡비와 경계 일치도
- 블록 이름·상대 삽입점 일치도
- 후보 영역에서 필터 선택된 레이어·엔티티 히스토그램 일치도
- 정규화 Anchor·선분 형상 일치도
- 우측 하단 `Scale` 라벨과 축척값의 상대 위치 일치도
- 내부 축척값과 선택 프로파일의 정확 일치 여부
- 변환 잔차와 Plot Window 유효성

내부 축척값 일치는 단순 가중 점수가 아니라 자동 승인 필수 조건으로 사용한다. 파일명, 도곽 크기 또는 다른 주석의 축척 문자열이 내부 `Scale` 셀 값을 대체할 수 없다.

### 8.4 교정 절차

생산 임계값과 가중치는 문서 작성 시 임의로 정하지 않는다.

1. 실제 도면에 정답 도곽·축척·플롯 영역을 라벨링한다.
2. 가중치 합이 1인 제한된 후보군을 결정론적 격자 탐색으로 평가한다.
3. 잘못된 자동 승인과 잘못된 축척 승인이 0건인 후보만 유지한다.
4. 그중 올바른 자동 승인 수와 최소 점수 차이가 가장 큰 조합을 선택한다.
5. 별도 검증 세트에서도 오승인 0건을 통과해야 프로파일을 승인한다.
6. 조건을 만족하는 조합이 없으면 자동 매칭을 활성화하지 않고 Anchor/Marker 보강을 요청한다.

교정 전 상태에서는 `auto_match_enabled = false`이며 dry-run과 프로파일 등록만 허용한다. 문자열형 임계값이나 임의 기본값은 설정 검증에서 거부한다.

## 9. Plot Window 변환

대상 DWG에 저장된 Plot Window를 복사하거나 보정하지 않고, 승인된 축척 프로파일의 참조 영역을 대상 도곽 좌표로 새로 계산한다.

1. 내부 축척값으로 프로파일을 선택하고 예상 도곽 크기를 확정한다. A3 기준 모델 크기는 `420 × (분모/분자)` × `297 × (분모/분자)` mm다.
2. 기준 도곽의 Scale Anchor와 참조 Plot Window 네 모서리를 도곽 로컬 좌표로 저장한다.
3. 대상 Scale Anchor를 기준으로 0°·90°·180°·270° 회전 후보별 평행이동을 계산한다.
4. 각 후보의 도곽 모서리, 제목란, Scale 셀 방향, 비대칭 Anchor 잔차를 검사한다.
5. 유일하게 통과한 회전 후보의 변환을 참조 Plot Window 네 모서리에 적용한다.
6. 변환된 네 점의 축 정렬 최소·최대 좌표를 `SetWindowToPlot`에 사용한다.
7. 도곽 회전값에 대응하는 검증된 `PlotRotation` 매핑을 적용해 PDF 내용을 정방향 A4 가로로 만든다.
8. 임시 DWG의 Layout에 Window Plot, Fit to Paper, Center Plot, PC3, 용지, CTB, 선가중치를 명시적으로 다시 설정한다.

회전 후보가 없거나 둘 이상 통과하는 경우 E304, 예상 크기·Anchor가 맞지 않으면 E307, 계산 Window의 폭·높이 0, 비정상 종횡비, 과도한 겹침 또는 도곽 이탈은 E309로 보류한다. 대상 DWG의 기존 Plot Window는 어떤 오류 상황에서도 폴백으로 사용하지 않는다.

## 11. 출력 이름과 충돌

- 첫 도곽: `<원본명>.pdf`
- 이후 도곽: `<원본명>_2.pdf`, `<원본명>_3.pdf`
- 축척 라벨은 PDF 파일명에 넣지 않는다.
- 복사본: `<이름> - 복사본.pdf`, 이후 `<이름> - 복사본 2.pdf`
- Y 내림차순, 같은 행은 X 오름차순, 동점은 Handle 순으로 정렬한다.
- 기존 PDF는 승인 없이 교체하지 않는다.
- 덮어쓰기는 새 PDF 검증 후 원자적 교체하며 실패 시 기존 PDF를 보존한다.

## 12. PDF 검증

최종 이동 전에 다음을 모두 확인한다.

- 파일 존재, 최소 크기, `%PDF-` 헤더
- pypdf 파싱 성공
- 정확히 1페이지
- MediaBox/CropBox가 A4 가로 297 × 210 mm와 허용 오차 내 일치
- 페이지 회전과 실효 방향이 가로
- 렌더러로 1페이지 렌더 가능
- 렌더 결과가 완전한 백지 페이지가 아님
- 작업 로그의 도곽 수와 PDF 수 일치
- 적용 프로파일 ID와 변환 Plot Window 기록 존재

pypdf는 빈 페이지나 객체 누락을 단독 판정하지 않는다. 렌더 성공과 비백지 검사는 운영 실패 조건으로 사용한다.

선 하나, 도곽 일부, 표제란 격자 일부처럼 통상 배율에서 사람이 구분하기 어려운 래스터 차이는 운영 실패 조건으로 사용하지 않는다. 픽셀 단위 또는 선 단위 기준 PDF 일치 검사는 개발 진단에서만 수행하며, 차이가 검출돼도 PDF 구조·페이지 규격·Scale·도곽 수·비백지 조건이 정상이면 결과를 저장한다. 필요할 때만 W610 비차단 경고를 기록한다.

## 13. 오류 처리

- 공통 환경 오류(E200~E214): 전체 작업 중단
- 파일 안정화·개별 DWG 오류(E215, E400 등): 해당 DWG만 보류 또는 실패
- 템플릿 오류(E300~E309): 해당 도곽만 보류 또는 실패
- 플롯·PDF 오류(E410~E420): 최종 저장 금지, 다음 독립 작업 계속
- 충돌 미승인(E500): 해당 출력만 건너뜀
- 예상 외 오류(E900): 현재 작업공간 보존, 소유 세션만 안전 종료, 로그 기록

이번 축척 판정과 직접 관련된 코드는 다음처럼 단일 의미로 사용한다.

- E303: 학습된 상대 위치에서 `Scale` 라벨 또는 바로 아래 축척값을 읽지 못함
- E304: 내부 축척값과 프로파일 형상이 모순되거나 자동 승인 가능한 단일 후보가 없음
- E305: 기준 템플릿 파일명이 등록 규칙과 맞지 않음
- E307: 도곽 형상, Anchor 또는 허용 변환 조건이 맞지 않음
- E308: 등록된 기준 템플릿의 해시가 승인 시점과 다름
- E309: 변환된 Plot Window가 비정상 또는 다른 도곽과 과도하게 겹침
- W610: 선택적 래스터 진단에서 미세 선·색상·CTB 차이가 발견됐으나 운영 필수 검사는 통과함

오류 메시지는 오류 코드, 대상 파일, 실패 단계, 사용자 조치, 사용 가능한 PC3/CTB/프로파일 후보를 포함한다. 전체 도면 텍스트와 라이선스 키는 로그에 남기지 않는다.
