- 개발 관리 시작점: [AutoCAD 개발 허브](../../autocad/README.md)

## 1. 결론과 목표

현재 GstarCAD 기반 DWG→PDF APP의 판정·배치 처리 로직을 유지하면서 Windows용 일반 AutoCAD를 선택할 수 있는 구조를 준비한다. AutoCAD가 없는 PC에서도 모의 테스트와 공통 구조 개발은 가능하지만 실제 설치·버전·라이선스·PDF 결과 검증 전에는 AutoCAD 지원 완료로 표시하지 않는다.

본 명세의 기능·인터페이스·기본값은 **설계 제안**이다. 사용자 승인 후 상세 구현 계획을 작성하고 작업 단위별로 구현한다. 개발 환경 부재를 이유로 테스트 결과를 추정하거나 NOT_RUN을 PASS로 처리하지 않는다.

## 3. 범위

### 포함

- Windows x64 일반 AutoCAD를 우선 목표로 하는 선택형 CAD 연결 모듈.
- 기존 GstarCAD 기본 동작과 설정 파일 하위 호환.
- 설치 후보 발견, 사용자가 선택한 CAD/버전 확인, 미설치·모호성·지원 제외 안내.
- 기존 13종 템플릿, Scale 판정, 이동/직각 회전, 공란/N/A 구조 판정 재사용.
- APP 소유 CAD 한 개로 파일별 순차 처리, 실패 격리, 원본 불변, 사용자 CAD 보호.
- AutoCAD 없는 환경의 모의 테스트와 실제 CAD 시험 결과를 분리하는 검증/배포 상태.
- GitHub에서 문서·진행 상태·작업 코드·검증 근거를 공유하는 협업 절차.

### 제외

- AutoCAD LT, Mac, Web, 모든 연도 버전 보장, 수직 제품군 일괄 지원.
- CAD 자동 설치, 라이선스 취득/활성화, LISP 보안 정책 자동 완화.
- 새로운 도곽 양식/축척 추가, 다중 도곽·여러 장 도면, 병렬 CAD 다중 실행.
- 클라우드 변환, 고객 DWG 자동 업로드, GstarCAD 기능 제거.
- 무응답 COM 강제 중단 watchdog의 신규 개발. 현재 제한을 문서화하고 별도 승인 작업으로 관리한다.

## 6. 제안 구조와 책임

```text
GUI / CLI / config
        ↓ 명시적 provider와 후보 선택
CAD provider factory
   ├─ GstarCAD adapter
   └─ AutoCAD adapter (experimental)
        ↓ 공통 세션/문서 계약
ConversionService → 기존 템플릿 판정 / 임시복사 / PDF검증 / 결과보고
```

- 탐지: 제품별 레지스트리 후보·실행파일 정보를 읽고 정규화. 임의 실행파일/등록되지 않은 ProgID는 받지 않는다.
- 세션: 생성·소유권 증명·문서 수명·종료·복구 책임. 기존 열린 CAD에 붙는 방식으로 대체하지 않는다.
- 문서 어댑터: Scale/구조 스냅샷 제공. 좌표계·블록 인스턴스·한도 검증 의미 유지.
- 플롯 어댑터: 실제 장치/용지/CTB 준비, Window 적용, 파일 출력, 제품별 회전 처리. 공통 PDF 품질 검증은 유지.
- 변환 서비스: 프로파일 선택·작업 순서·출력 충돌·원자적 게시 담당. 공급자별 클래스 `isinstance`에 의존하지 않도록 경계를 정리한다.
- 증거: 엔진·버전·커밋·설정·입력 표본 해시·검증 결과를 묶는다. 버전 문자열만으로 호환 승인하지 않는다.

현재 연결 지점은 `configuration.py`, `cli.py`, `desktop_launcher.py`, `batch_session.py`, `conversion_service.py`, `gstarcad/*`이다. 정확한 신규 파일명·함수 시그니처·이동 범위는 명세 승인 후 상세 구현 계획에서 확정한다. 전체 저장소 재구조화는 하지 않는다.

## 7. 설정 및 사용자 동작 제안

다음은 **미구현 제안**이며 현재 실행 파일이 지원하는 옵션이 아니다.

```toml
[cad]
provider = "gstarcad"
allow_experimental_autocad = false
# prog_id는 설치 후보에서 선택한 정확한 값이 필요한 경우에만 지정
```

- 기존 `[gstarcad]`만 있는 설정은 현재 의미 그대로 읽는다. 새 `[cad]`와 구 설정을 함께 주어 값이 충돌하면 명시 오류로 처리하고 우선순위를 숨기지 않는다.
- AutoCAD 선택은 `provider="autocad"`와 실험적 opt-in을 모두 요구한다. GUI는 미검증 경고를 표시한다.
- 후보가 여러 개이고 선택이 없으면 GUI는 선택을 요구하고 비대화형 CLI는 실행 전 실패한다. 개발자가 현재 PC의 ProgID를 공용 설정에 하드코딩하지 않는다.
- CAD 미설치 PC에서도 문서 열기·모의 테스트·CAD를 시작하지 않는 자체 검사는 가능해야 한다. 자체 검사 성공과 실제 변환 가능 상태를 구분한다.
- 오류 문구는 선택한 CAD 이름·문제 단계·사용자 조치를 표시한다. 새 오류코드 번호는 기존 `errors.py` 체계 확인 후 구현 계획에서 배정한다.

실기 비교는 페이지수·A4가로·비공백 외에 도곽/영역/방향/문자누락/선굵기/흑백을 확인한다. 엔진 간 픽셀 차이는 드라이버/폰트 차이일 수 있으므로 동일성을 가정하지 않는다. 차이는 근거를 기록하고 사용자 수용 여부를 받는다. GstarCAD 동일 엔진 회귀에서는 기존 픽셀 비교 도구를 재사용한다.

비정상 표본은 비균일 축척,지원 외 축척/회전,중복 Scale,잘못된 값,미설치/여러 버전,LISP차단,출력 잠금,기존 사용자 CAD,소유권 미확인,한글 경로를 포함한다. 실패가 다음 DWG 처리와 원본 보호를 깨뜨리지 않아야 한다.

성능은 시작/종료 시간과 파일별 열기/판정/플롯/검증 시간을 분리해 측정한다. GstarCAD에서 측정한3.12초/82.7%를 AutoCAD에 전용하지 않는다.

## 9. 위험·미해결 입력과 결정 규칙

| 항목 | 처리 규칙 |
|---|---|
| 실제 제품·버전 없음 | 연도별 지원 목록 비워두고 AC-06 환경 확보 전 실기 차단 |
| COM 생성이 기존 프로세스를 반환 | 기존 사용자 CAD에는 작업/종료하지 않고 오류. 이름으로 전체 종료 금지 |
| 여러 프로세스가 동시에 생겨 소유권 모호 | 명확히 소유가 증명된 핸들 외 종료 금지. 증거와 실패 보고 |
| 동기 COM 무응답 | 현재 timeout이 강제중단 보장이 아님을 안내. 별도 watchdog 승인 없이 지원완료 근거로 삼지 않음 |
| PDF 방향/글꼴/CTB 차이 | 제품별 실제 출력으로 판단. GstarCAD 규칙 강제 적용 금지 |
| 다른 PC의 개발 도구 미설치 | 설치/자격증명은 사용자 환경 준비. 기존 경로를 복사한 것으로 준비완료 판단 금지 |
| 다른 템플릿 추가 요구 | 별도 명세로 분리; 이번 작업에 몰래 포함하지 않음 |

납기·투입시간·성능 목표치는 근거가 없어 산정하지 않았다. 실제 AutoCAD 환경 확보 담당/시점은 `[입력 필요]`이며 오프라인 구조 개발 범위와 구분한다.
