# DWG→PDF 배치 세션 및 Scale Fallback 개정 설계

**작성일:** 2026-07-16
**상태:** 사용자 설계 승인 완료, 문서 검토 대기
**적용 범위:** Task 4 이후 GstarCAD 세션, 템플릿 판정, 배치 오류 처리

## 1. 결론

APP은 배치 작업마다 자신이 소유하는 GstarCAD 프로세스 하나를 생성하고, 그 프로세스에서 여러 DWG를 순차적으로 열고 닫는다. 전체 배치가 끝나면 APP이 생성한 프로세스만 종료하며 사용자가 별도로 실행한 GstarCAD 프로세스에는 연결하거나 종료 명령을 보내지 않는다.

도면 내부 Scale 값이 정상일 때는 해당 축척 프로파일로 구조를 검증한다. Scale 값이 비어 있거나 `N/A`이면 사용자가 등록 단계에서 지정한 13개 기준 템플릿의 도곽·표제란 구조를 모두 비교하여 유일하게 일치하는 프로파일을 선택한다. 13개 규격 이외의 도면, 일치하지 않는 도면, 동점인 도면은 자동 변환하지 않는다.

개별 파일 실패는 배치 전체를 중단하지 않는다. 실패 파일을 안전하게 닫고 다음 파일을 계속 처리하며, 작업 완료 후 성공·실패 요약과 파일별 오류 사유를 별도 결과 창에 표시한다.

## 2. 기존 설계 대체 규칙

이 문서는 기존 `2026-07-16-dwg-to-pdf-design.md`와 `2026-07-16-dwg-to-pdf-implementation.md` 중 다음 전제를 대체한다.

1. `입력 DWG마다 GstarCAD 프로세스 하나 생성`을 `배치마다 GstarCAD 프로세스 하나 생성`으로 대체한다.
2. `Scale 값 미검출 시 E303으로 즉시 보류`를 다음 조건으로 대체한다.
   - Scale 값이 공란 또는 `N/A`: 13개 승인 템플릿 구조 기반 fallback 실행
   - Scale 값이 정상 비율: 해당 프로파일로 구조 검증
   - 그 밖의 잘못된 문자열: 해당 파일 실패
3. 한 파일의 COM·형상·플롯·PDF 검증 오류가 전체 배치를 중단한다는 해석을 금지한다. 파일 단위 오류 격리를 적용한다.

그 밖의 원본 보호, 대상 DWG의 저장 Plot Window 미사용, A4 가로, Fit, Center, `monochrome.ctb`, 선가중치, 0°/90°/180°/270° 회전 지원 조건은 유지한다.

## 3. 지원 범위

지원 대상은 사용자가 제공하고 승인한 13개 템플릿 규격으로 제한한다.

- 1:1, 1:2, 1:5, 1:10, 1:20, 1:50, 1:100
- 2:1, 5:1, 10:1, 20:1, 50:1, 100:1

다음 입력은 지원 범위 밖이다.

- 승인된 13개 프로파일과 일치하지 않는 도곽 또는 표제란
- 임의 배율, 비균일 축척, 반사, 전단 또는 특이 변환
- 90도 단위가 아닌 도곽 회전
- 여러 프로파일이 동일 신뢰도로 남는 모호한 구조
- 하나의 도면에 Scale 셀이 둘 이상 존재하는 입력

지원 범위 밖의 입력은 해당 파일만 실패 처리한다. 자동 보정하거나 가장 가까운 프로파일을 강제로 선택하지 않는다.

## 4. 배치 GstarCAD 세션

### 4.1 소유권

1. 배치 시작 전 실행 중인 `gcad.exe` PID 집합을 기록한다.
2. `DispatchEx`로 새 GstarCAD 인스턴스를 생성한다.
3. 새 Application의 HWND가 가리키는 PID가 실행 전 집합에 없고 실행 후 집합에 존재하는지 확인한다.
4. 조건이 충족될 때만 PID를 APP 소유로 기록한다.
5. 소유권을 증명할 수 없으면 파일을 열지 않고 배치를 실패로 종료한다.

사용자가 기존에 실행한 GstarCAD 프로세스는 검색 대상일 수 있지만 제어·연결·종료 대상이 아니다.

### 4.2 수명주기

```text
배치 시작
  → 전용 GstarCAD 프로세스 생성 및 소유권 증명
  → DWG A 열기 → 판정 → 임시 복사본 플롯 → 닫기
  → DWG B 열기 → 실패 기록 → 닫기
  → DWG C 열기 → 판정 → 임시 복사본 플롯 → 닫기
  → 결과 집계
  → APP 소유 GstarCAD 종료
  → 결과 창 표시
```

세션은 여러 문서를 동시에 열지 않고 한 번에 하나만 연다. 현재 문서가 완전히 닫힌 것을 확인한 다음 파일을 연다. 파일 처리 후 COM 문서 참조와 SelectionSet을 해제하여 장시간 배치에서 누적 상태가 다음 파일에 영향을 주지 않게 한다.

### 4.3 복구와 종료

- 파일 처리 예외가 발생하면 현재 문서를 저장하지 않고 닫고 다음 파일을 처리한다.
- 문서 닫기가 실패하면 APP 소유 GstarCAD를 종료하고 새 전용 프로세스를 생성한 뒤 남은 파일을 계속 처리한다.
- GstarCAD 프로세스 자체가 종료되거나 COM 연결이 끊어지면 새 소유 프로세스를 생성해 남은 파일을 계속 처리한다.
- 정상 종료 제한시간을 초과한 경우에도 PID 숫자 기반 종료는 금지한다. 소유권 입증 직후 확보한 정확한 Windows 프로세스 핸들만 대기·종료 대상으로 사용한다.
- 소유권이 증명되지 않은 PID에는 어떤 경우에도 종료 명령을 보내지 않는다.

## 5. Scale 판정

### 5.1 정상 Scale

`Scale` 라벨은 도면당 정확히 하나라는 운영 조건을 적용한다. 값이 승인 비율 중 하나이면 해당 프로파일 하나로 후보를 제한한다. 이후 도곽 크기, 표제란 구조, 방향 Anchor 및 0°/90°/180°/270° 회전 정합을 검증한다. 정상 Scale 값이 있어도 구조가 해당 프로파일과 일치하지 않으면 해당 파일을 실패 처리한다.

### 5.2 공란 또는 N/A Fallback

`Scale` 라벨은 존재하지만 그 값이 공란이거나 대소문자·주변 공백을 무시한 `N/A`이면 구조 기반 fallback을 실행한다.

1. 등록 단계에서 사용자가 지정한 각 템플릿의 도곽 영역과 참조 Plot Window를 승인 프로파일에 저장한다.
2. 도곽 모서리, 표제란 격자, Scale 라벨 위치, 비대칭 방향 Anchor를 도곽 로컬 좌표로 정규화한다.
3. 대상 도면에서 서버 측 SelectionSet 필터와 제한된 중첩 블록 탐색으로 필요한 객체만 수집한다.
4. 13개 프로파일 각각에 대해 0°·90°·180°·270° 후보를 생성한다.
5. 도곽 크기·종횡비, 모서리 잔차, 표제란 상대 위치, 방향 Anchor 잔차를 검증한다.
6. 보정된 임계값과 최소 점수 차이를 모두 만족하는 유일한 후보만 승인한다.
7. 승인 프로파일의 참조 Plot Window에 검출된 강체 변환을 적용해 대상 Plot Window를 계산한다.

파일명, 대상 DWG에 저장된 Plot Window, EXTMIN/EXTMAX만으로 축척 또는 출력 영역을 결정하지 않는다. EXTMIN/EXTMAX는 제한 검색 범위와 계산 결과의 포함 여부를 확인하는 보조값으로만 사용한다.

### 5.3 잘못된 값과 모호성

- `N/A`와 공란 이외의 비율 형식 오류: 파일 실패
- 승인된 13개에 없는 정상 비율: 파일 실패
- Scale 라벨 없음: 파일 실패
- Scale 라벨 둘 이상: 파일 실패
- 구조 후보 없음: 파일 실패
- 구조 후보 동점 또는 최소 점수 차이 미달: 파일 실패

## 6. 파일 단위 오류 격리

각 입력 파일은 독립적인 작업 결과를 가진다.

- 성공: PDF 경로와 검증 결과 저장
- 실패: 원본 DWG 경로, 오류 코드, 사용자용 사유, 기술 상세 저장
- 건너뜀: 출력 이름 충돌 정책 등에 따라 사용자가 의도적으로 제외한 상태 저장

한 파일의 실패로 이미 생성·검증된 다른 PDF를 삭제하지 않는다. 실패한 파일에서 생성된 불완전 PDF와 임시 DWG만 제거한다. 원본 DWG는 모든 경로에서 저장하지 않으며 처리 전후 SHA-256과 수정시간을 확인한다.

## 7. 결과 창

배치 종료 후 하나의 결과 창을 표시한다.

```text
DWG → PDF 변환 완료

전체: 25개
성공: 22개
실패: 3개

[실패 목록]
XXX-XXX.DWG — 비균일 블록 축척이 검출되었습니다.
YYY-YYY.DWG — Scale이 N/A이며 13개 템플릿 중 일치하는 구조가 없습니다.
ZZZ-ZZZ.DWG — GstarCAD 문서를 열 수 없습니다.
```

각 실패 항목은 최소한 파일명과 사람이 이해할 수 있는 사유를 포함한다. 기술 오류 코드와 상세 로그 경로는 펼쳐보기 또는 로그 파일에서 제공한다. 결과 창을 닫아도 성공한 PDF와 로그는 유지한다.

## 8. 오류 분류

- `E201`: APP 전용 GstarCAD 세션 생성·소유권 증명 실패
- `E203`: 문서 열기·닫기 또는 COM 연결 실패
- `E303`: Scale/도곽/변환 구조 검출 실패
- `E304`: 템플릿 또는 회전 후보가 모호함
- `E305`: 지원하지 않는 Scale 값 또는 형식 오류
- `E307`: 지원하지 않는 도곽 회전·변환
- `E310`: Scale 공란·N/A 구조 fallback 일치 없음
- `E311`: 배치 중 GstarCAD 세션 복구 실패
- 플롯·PDF 검증 오류 코드는 기존 설계의 정의를 유지한다.

내부 예외 메시지를 그대로 결과 창에 노출하지 않는다. 안정된 오류 코드와 사용자용 한국어 메시지로 변환하고 기술 상세는 로그에 기록한다.

## 9. 테스트 및 승인 기준

### 9.1 단위·모의 COM 테스트

- 한 세션에서 A·B·C 문서를 순차적으로 열고 닫음
- 한 파일 실패 후 다음 파일이 정상 처리됨
- 문서 닫기 실패 시 세션을 교체하고 남은 파일 계속 처리
- 기존 사용자 PID는 종료 대상이 되지 않음
- APP 소유 PID만 정상 종료 또는 제한적 강제 종료
- Scale 정상값은 해당 프로파일 하나만 검증
- Scale 공란과 `N/A`는 13개 프로파일 전체 구조 비교
- 공란/N/A fallback에서 유일 후보만 승인
- 후보 없음·동점·임계값 미달은 해당 파일만 실패
- 비균일 축척·반사·전단·비유한 좌표는 해당 파일만 실패
- 실패 목록에 파일명·오류 코드·사용자용 사유가 보존됨

### 9.2 실제 GstarCAD 통합 테스트

- 사용자 GstarCAD를 미리 실행한 상태에서 배치 전용 프로세스가 별도로 생성됨
- 3개 이상의 DWG를 하나의 APP 소유 프로세스에서 순차 처리
- 중간 파일에 의도적 실패를 넣어도 후속 파일이 PDF로 변환됨
- 배치 종료 후 APP 소유 프로세스만 종료되고 사용자 프로세스는 유지됨
- 모든 원본 DWG의 SHA-256과 수정시간이 유지됨
- Scale 공란 또는 N/A 시험 도면이 구조에 따라 올바른 13개 프로파일로 유일 판정됨
- 13개 범위 밖 시험 도면은 PDF를 만들지 않고 실패 목록에 포함됨

### 9.3 완료 기준

1. 실제 GstarCAD에서 하나의 APP 소유 프로세스로 다수 도면을 처리한다.
2. 개별 파일 실패가 배치 진행을 중단하지 않는다.
3. Scale 공란·N/A 도면이 승인된 13개 구조 중 유일한 프로파일로 판정된다.
4. 지원 범위 밖 또는 모호한 도면은 잘못된 PDF 대신 명확한 실패 결과를 남긴다.
5. 사용자 GstarCAD 프로세스와 모든 원본 DWG가 변경되지 않는다.

## 10. 명시적 비범위

- 13개 템플릿 이외 도면의 자동 학습
- 임의 축척값 또는 임의 용지 규격 지원
- 실행 중 새로운 템플릿을 자동 생성·승인
- 파일별 수동 Plot Window 재지정
- 비균일 축척·반사·전단 도면의 자동 보정
- 여러 GstarCAD 프로세스를 이용한 병렬 변환
