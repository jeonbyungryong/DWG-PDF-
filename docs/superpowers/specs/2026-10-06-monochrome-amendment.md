## 1. 결론과 승인 범위

GstarCAD와 AutoCAD의 작업용 DWG 복사본에 동일한 흑백 보정 규칙을 적용한다. 기존 AutoCAD True Color 보정 로직을 공통화하고 GstarCAD 플롯 직전에 연결하는 제한된 변경이다. PDF를 이미지로 다시 만들거나 원본 DWG를 수정하는 방식은 사용하지 않는다.

사용자는 기존 색상 유지 대신 **임시 도면 보정에 의한 완전 흑백 통일**을 선택했고, 추가 수정 명세의 작성 및 GitHub 게시를 요청했다. 이 선택은 방향 확정이며 이 문서의 세부 예외·검증 기준에 대한 승인은 별도다. 본 명세 승인 전 제품 구현을 시작하지 않는다. MAIN 병합·새 실행 ZIP·공식 지원 및 배포 승인은 포함하지 않는다.

승인 갱신(2026-10-06): 게시 커밋 `d3d75520642a597e8c8de9b45eea3be42dc67505`에 대한 사용자 `진행해`로 MC-S1을 승인받고 구현을 시작했다. [구현·검증 인계](../../autocad/MC-01-HANDOFF-2026-10-06.md)를 따른다. 규칙은 변경하지 않았으며 성능 구조 변경과 MC-S3은 별도 승인이다.

## 2. 확인된 사실과 근거

| 구분 | 사실/결정 | 근거 |
|---|---|---|
| 사용자 결정 | 원본이 아닌 작업용 복사본을 보정해 완전 흑백으로 통일 | 현재 대화의 `후자로 진행해` |
| 사용자 요청 | 수정 명세 작성·개발 브랜치 게시 후 승인과 구현을 분리 | 현재 대화의 명세 필요 여부 질문 및 `진행해` |
| 코드 확인 | AutoCAD는 플롯 전 `prepare_monochrome`을 호출하며 GstarCAD에는 해당 연결이 없음 | 기준 커밋의 두 document 어댑터 |
| 코드 확인 | AutoCAD 보정은 RGB 흰색을 제외한 True Color를 ACI7로 바꾸며 모든 검사 후 변경을 시작 | `src/dwg_to_pdf/autocad/monochrome.py` |
| 과거 실기 | GstarCAD2026 기본43종 변환/기대값 통과,185.23초;43개 모두 잔존 색상 | [PC-A 회귀 기록](../../autocad/PC-A-REGRESSION-2026-10-04.md) |
| 과거 비교 | 이전 버전과 동일 엔진의1:1 샘플1개는 판정/144dpi 픽셀 동일 | 위 기록; 전체 이전 버전 비교 근거가 아님 |
| 미검증 | 공통화 이후 GstarCAD/AutoCAD의 흑백·선굵기·처리 시간 | 본 변경 기준 NOT_RUN |

과거 PASS와 성능 수치는 새 보정의 성공·속도 보장이 아니다. 상위 명세의 역사적 상태표와 최신 이슈 상태가 다르면 최신 인계 기록을 따른다.

## 3. 범위와 비목표

포함: Windows GstarCAD 및 실험적 일반 AutoCAD의 기존13종 템플릿 변환, 내부 블록·속성·레이어의 True Color 보정, 파일별 실패 격리, 원본/사용자 CAD 보호, 흑백 및 성능 감사.

제외: 새 템플릿/축척, LT/Mac/Web 지원, CAD 보안 정책 완화, 외부참조 파일 수정, 이미지·OLE·재질/렌더링의 신규 색상 변환, PDF 래스터화, 병렬 CAD, watchdog 신규 개발, 고객 자료 자동 업로드. 대상 외 색상이 발견돼도 지원을 추정하거나 감사 기준을 완화하지 않는다.

## 5. 수정 구조와 순서

1. 기존 AutoCAD 보정 함수를 `src/dwg_to_pdf/cad/` 아래 공통 모듈로 이동한다. 공통 함수는 승인된 작업용 raw document만 받아 사전 검사/보정하거나 E410을 발생시킨다.
2. 기존 AutoCAD import 경로는 호환 위임을 남겨 기존 호출자와 시험을 깨뜨리지 않는다. 공통 모듈의 오류 설명은 특정 CAD만 지칭하지 않는다.
3. GstarCAD와 AutoCAD의 `plot_pdf`에서 기존 판정 완료 후, 플롯 설정/출력 전에 공통 준비를 한 번 호출한다. SCALE 판정과 구조 스냅샷은 변경하지 않는다.
4. 모의 시험의 보호/예외 경로와 두 어댑터 연결을 보강하고, 기존 회귀 및 실제 출력 감사·성능 비교를 실행한다.

주요 변경 예정 파일: `cad/monochrome.py`(신규 공통 모듈), `autocad/monochrome.py`(호환 위임), `autocad/document.py`, `gstarcad/document.py`, 관련 단위/통합 시험 및 검증 문서. 구현 시 실제 인터페이스와 기존 시험을 확인하고 불필요한 재구조화를 하지 않는다. CAD API/LISP 보안 설정·템플릿·PC3/CTB 자산을 자동 변경하지 않는다.

## 6. 검증 기준

### 모의/오프라인

- RGB 색상·순백색·ACI·ByLayer·ByBlock·레이어·내부 블록·일반/상수 속성·반복 실행.
- XRef,64/5000 한도 경계/초과,잘못된 값,읽기/쓰기 실패,검사 완료 전 무변경,부분 변경 후 저장/게시 금지.
- 실패→정상 파일의 동일 배치 처리,소유권/원본 보호,어댑터별 플롯 전 준비 순서,기존 import 호환.
- 실패 재현→최소 구현→집중 시험→전체 오프라인 회귀. SKIP/NOT_RUN을 PASS에 합산하지 않음.

### 성능

동일 PC/CAD/입력/PC3/CTB/설정에서 보정 전후를 비교한다. 기동·종료,열기,판정,흑백 준비,플롯,PDF 검증을 분리하고 배치 시간·파일별 중앙값/최대값·반복 횟수·오류를 기록한다. COM 계측 모드의 추가 비용은 순수 처리 시간과 분리한다.

185.23초는2026-10-04의 과거 측정이며 새 시험의 고정 성능 목표가 아니다. 사용자 승인된 지연 허용률/납기는 없다. 속도 저하를 숨기거나 임의 기준으로 합격시키지 않고 원인과 개선안을 보고한다. 무제한 COM 탐색이나 다른 성능 구조 변경이 필요하면 별도 수정안 승인을 받는다.

## 7. 위험·제한과 결정 규칙

- 색상만 바꾸어도 CTB 색상별 선굵기/농도 결과가 달라질 수 있다. 설정 무변경만으로 시각적 선굵기 보존을 주장하지 않는다.
- COM 전체 검사 비용이 늘 수 있다. 기존 빠른 추출과 보정 시간을 구분하며 미측정 성능 개선을 약속하지 않는다.
- 영상/외부참조/특수 객체가 본 보정으로 처리되지 않을 수 있다. 기존13종 제한을 유지하며 새 지원을 임의 추가하지 않는다.
- 정상 서명 뒤 손상 DWG의 modal/hang은 본 명세로 해결되지 않는다. 원래 고객 표본 부재와 기존G3 특수시험 미완료도 별도로 남는다.
- 흑백43종 PASS는 전체G3,AutoCAD 공식지원,새 frozen EXE/다른PC의G5,배포 승인을 대체하지 않는다.

| 단계 | 범위 | 현재 상태 |
|---|---|---|

| MC-S1 수정 명세 승인 | REV01의 규칙/예외/검증 기준 사용자 검토 | **2026-10-06 사용자 승인** |
| MC-S2 구현/회귀 | 실패 재현,공통화,오프라인/실기/성능,독립 리뷰와 개발 브랜치 인계 | 제한된 구현·검증,성능 저하/43종·AutoCAD NOT_RUN;인계 참조 |

MC-S1 승인 후 본 범위의 구현을 시작하며 세부 실행 순서는 기존 개발 계약/TDD에 따른다. 명세에서 벗어나는 기능·인터페이스·성능 구조 변경은 먼저 제안한다. 모든 게이트는 이슈에 커밋·명령·환경·PASS/FAIL/SKIP/NOT_RUN을 기록한다.
