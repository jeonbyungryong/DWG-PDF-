## 추가 개선: CAD 내부 일괄 추출

### 결론 및 확인된 사실

CAD 내부에서 문자·블록·후보 영역 기하를 일괄 수집하고 기존 Python 검증 경로에 전달한다. 추출 전용 SDK는 필요하지 않는다. 정상 Scale 입력의 전체 처리시간은 약18초에서 약3초로 감소했다. 같은 PC의 제한된 템플릿 표본 결과이므로 모든 업무 도면에 대한 보장은 아니다.

| 검증 항목 | 확인 결과 |
|---|---|
| 13개 템플릿 선행 비교 | 중앙값18.037초 →3.054초, 83.07% 감소 |
| 13개 최종 재비교 | 중앙값18.037초 →3.121초, 82.70% 감소; 13/13 픽셀 동일 |
| 공란/N/A 확장 시험 | 13종×2상태 + 1:50/100:1의 회전 조합4개, 30/30 축척·회전 정답, 중앙값5.301초 |
| 출력 비교 | 13/13 축척·회전 동일, Window 절대오차≤1e-9, 144dpi RGB 픽셀 동일 |
| Python 자동화 | 660 passed, 10 skipped |
| UCS/화면 상태 | 이동·회전 UCS 및 화면 밖 보기에서도 52개 후보 점수/선분 수 동일 |
| Layout 격리 | 다른 Layout에 같은 위치의 Scale/도곽을 추가해도 현재 Layout의 52개 후보 및 Scale1개 유지 |
| 원본/프로세스 | DWG SHA-256·mtime 보존, APP 소유 CAD 종료 |
| 최종 EXE 실기 | 개발 PYTHONPATH 없이 8개 입력: 정상7개 PDF 성공, 비균일1개 예상 실패 후 나머지 계속 처리 |
| 배포 자체 검사 | RUNTIME_SELF_CHECK_OK, VALIDATION_BUNDLE_OK; 번들 LISP와 소스 SHA-256 동일 |

EXE 실기는 41.85초(8개 입력 및 CAD 시작/종료 포함)였으며 평행이동,90/270도,공란,N/A,1:50/100:1 공란90도를 포함했다. PDF7개 모두 1페이지 A4가로·비공백, 원본 해시/mtime 무변경, 잔류 APP CAD 없음. 종료코드1은 의도적으로 포함한 비균일 축척1개의 실패에 따른 정상 예상값이다.

### 변경 내용과 원인

1. 객체마다 Python↔CAD를 왕복하던 조회를 LISP 한 번의 읽기 전용 수집으로 대체했다. nonce·문서 경로·완료 표시·버전·응답 크기·객체 한도를 검사하고 기존 기하 검증을 재사용한다. 식별된 완료 오류만 기존 COM 추출로 복귀한다.
2. Scale 공란/N/A는 13종 도곽 구조로 먼저 템플릿을 선택한 뒤 그 템플릿의 값 칸만 검사한다. 중복 값/잘못된 값은 여전히 거부한다.
3. 회전 후 극소 좌표 오차가 수직 선분의 사전식 끝점 순서를 뒤집어 구조 점수0.8125를 만드는 현상을 실기로 확인했다. 양방향 끝점 대응 중 최소거리를 사용해 해결했다. 공차·점수 기준·일대일 선분 소비는 변경하지 않았다.
4. GstarCAD crossing 선택은 ActiveX에서도 화면 밖 도곽을 놓치는 것을 실기로 확인했다. 전체 타입 필터 후 현재 출력 Layout 소유 객체만 CAD 내부 WCS 경계상자로 제한하고 정확한 구조 비교를 이어간다. 다른 Layout에 추가한 동일 좌표 도곽이 섞이지 않는 것도 실기로 검증했다. 제품은 사용자의 UCS/화면 설정을 변경하지 않는다.
5. 90°/270°에서 생성되는 A4 세로 PDF는 벡터 콘텐츠와 page box를 회전해 A4 가로로 정규화한다. 비정상 용지나 예상하지 못한 회전 메타데이터는 E420으로 거부하며 임의 확대축소하지 않는다.

### 리스크와 추가 검증

- 30초 제한은 늦은 응답 거부와 파일 대기를 제한하지만, 정지한 동기 COM 호출을 강제 중단하는 watchdog은 아니다.
- 다른 PC의 LISP 보안 정책·GstarCAD 버전·Windows ACP 조합은 실기 NOT_RUN. 자동으로 보안 설정을 낮추지 않는다. `matching.use_native_extraction=false`는 기존 COM 호환 경로이다.
- 이번에 미리 열린 사용자 CAD는 없었다. PID 보호는 회귀 테스트로 확인했고, 동시 실행 실기는 별도로 필요하다.
- 고객 업무 도면22개는 D: 원본 경로가 없어 재시험 NOT_RUN. 다른 PC/clean-account도 NOT_RUN이다.
- 렌더 일치는 표본 출력 보존 증거이지 치수·설계 의미의 독립 검증이 아니다.

원시 증거: `.superpowers/sdd/native-extraction/`의 `all13.json`, `comparison-all13.json`, `final-all13.json`, `final-comparison.json`, `final-blank30.json`, `structure-probe.json`, `view-probe-fixed.json`, `layout-view-final.json`. 파생 DWG와 원시 증거는 로컬에 보존하며 외부 업로드하지 않았다.

배포 증거는 `build.log`, `frozen-final/smoke-result.json`에 보존했다. 코드 독립 리뷰의 PDF 회전 메타데이터, Scale 칸 불일치, viewport/UCS/Layout 혼입 지적을 수정·재현 검증했으며 최종 리뷰는 통합 가능으로 판단했다. 무응답 COM watchdog·타 PC 검증은 여전히 별도 후속 범위이다.

## 아래는 1차 성능 개선 이력 (추가 개선 전)

## 결론

동일 3개 승인 템플릿 비교에서 CAD 시작시간을 제외한 파일 처리시간 중앙값이 22.44초에서 18.03초로 19.7% 감소했다. 13개 승인 템플릿은 모두 변환 성공했다. 원본 보호와 배치 실패 격리는 유지했다.

다만 확장 시험에서 90°/270° 회전 및 Scale 공란/N/A 입력의 기존 오류를 확인했다. 기존 배포 소스에서도 재현되므로 성능 변경으로 생긴 회귀는 아니지만, 전체 요구사항 충족 또는 production 배포 완료로 판단하지 않는다.

## 확인된 사실

- 자동화 테스트: 628 passed, 10 skipped(6개 opt-in CAD, 4개 플랫폼 의존).
- 실제 CAD: 승인 템플릿 13/13 성공, 평균 파일 처리시간 18.09초.
- 비교 대상: TEMPLETE_1대1.DWG, TEMPLETE_1대50.DWG, TEMPLETE_5대1.DWG.
- 비교 3개 모두 축척·회전·출력영역 동일, Poppler 144dpi RGB 픽셀 동일.
- 실제 시험 전후 원본 DWG SHA-256/수정시각 동일, APP 소유 CAD 종료.
- 이번 실제 시험에는 미리 실행된 사용자 CAD가 없었음. 사용자 PID 보호는 회귀 테스트와 과거 실측 이력으로 구분하여 관리.
- frozen EXE에서 비균일 축척 실패 후 다음 평행이동 도면 변환 성공. 생성 PDF는 1페이지 A4 가로·비공백. CLI 종료코드 1은 앞 파일 실패에 따른 예상 결과.

## 변경 및 분석

1. CAD 객체 종류, 좌표, 블록 이름을 한 번 읽어 재사용한다.
2. 변환 전용 경량 탐색에서는 미사용 문자 경계정보와 비문자 객체의 존재하지 않는 문자 속성 조회를 생략한다. 등록용 경계정보와 기존 기하 오류 검증은 유지한다.
3. 선호 용지 후보의 실제 A4 치수를 우선 검증한다. 복수 후보 모호성 및 장치/CTB 오류는 그대로 검사한다.
4. 블록 정의 캐시는 보류했다. 대표 도면의 29개 정의가 각각 1회만 조회되어 추가 캐시 효과가 입증되지 않았다.

기존 배포 소스와 개선 소스 각각 1개 비교 배치이며, 큰 표본의 통계적 성능 보장은 아니다. 개선 값은 13개 템플릿 배치 중 같은 입력의 결과이다. 파일 처리시간에는 PDF 검증이 포함되며 CAD 시작시간은 제외된다. 속성별 진단 계측 결과는 계측 오버헤드가 있어 위 처리시간과 혼합하지 않았다.

## 리스크와 한계

| 추가 실제 CAD 입력 | 개선 결과 | 기존 배포 소스 대조 |
|---|---|---|
| 평행이동 | 성공 | 이번 대조 미실행 |
| 180° 회전 | 성공 | 이번 대조 미실행 |
| 90°/270° 회전 | E420 | 동일 실패 |
| Scale 공란/N/A | E304 | 동일 실패 |
| 비균일 축척 | 예상 E303 | 이번 대조 미실행 |

회전 실패는 실제 PDF MediaBox가 약 210×297mm이고 /Rotate=0으로 생성되어 A4 가로 검증에 실패한 것이다. 단순히 검증을 완화해 허용하면 출력 방향 요구사항을 위반하므로 변경하지 않았다.

공란/N/A 실패에서는 여러 프로파일의 후보 영역에 일반 주석과 선 객체가 함께 들어왔다. 관찰한 후보 목록을 근거로, 프로파일별 구조와 값 셀의 연결 순서를 재검토할 필요가 있다. 단순한 선 객체 제외만으로 해결된다고 판단하지 않는다.

이전 고객 도면 22개는 원본 D: 경로가 없어 이번 재시험 NOT_RUN이다. 다른 PC 및 clean-account 시험도 NOT_RUN이다. 픽셀 일치는 비교 표본의 출력 동일성 증거이며 치수/도면 의미 정확성의 독립 보증은 아니다.

## 리뷰와 후속 실행안

- ASTRA 독립 최종 리뷰에서 제품 코드의 Critical/Important 신규 문제는 발견되지 않았다.
- 진단 도구가 사용자 PID 보존 여부를 최종 성공 판정에 포함하지 않던 P2 지적을 수정하고 3개 회귀 테스트를 추가했다.
- 경량 뷰가 원본 플래그와 캐시 객체를 변경하지 않는다는 단일 명시 테스트 보강은 Minor 후속 항목으로 남겼다. 기존 하위 클래스/탐색 회귀 테스트는 통과했다.
- 승인된 성능 개선 범위에서는 기존 탐색 의미를 유지했다. 회전 출력 및 공란/N/A 판정 재설계는 별도 수정 항목으로 분리했다.
- 다음 권고 순서: 기존 회전/공란 오류 수정 → 사용자 실제 업무 도면 22개 재시험 → 다른 PC 시험 → 배포 승인 후 기본 브랜치 반영.
- 검증본은 dist/dwg-to-pdf-validation 폴더 전체를 사용한다. EXE만 분리하지 않는다.

## 증거 및 검증 기준

로컬 원시 증거는 .superpowers/sdd/2026-10-02-dwg-performance/ 아래에 보존한다.

- baseline-repeat.json, improved-all13.json, comparison.json: 처리시간과 출력 동일성.
- baseline-variants.json, improved-variants.json: 기존/개선 변형 입력 결과.
- frozen-smoke/smoke-result.json: 배포 실행 파일의 실패 격리·원본 보호·종료 결과.
- fixtures/manifest.json: 파생 시험 도면 생성 및 원본 보호.
- build.log: 빌드 및 자체 검사.
- 재현 도구: tools/benchmark_conversion.py, tools/compare_benchmark_results.py, tools/generate_performance_fixtures.py, tools/smoke_frozen_bundle.py.

원시 증거 및 파생 시험 파일은 재현성을 위해 로컬에 유지하며 이번 작업에서 외부 업로드하지 않는다.
